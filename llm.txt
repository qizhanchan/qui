# qui — AI-native Go GUI framework

qui is a retained-mode desktop GUI framework written in Go. It runs on
GLFW + OpenGL with a custom CPU-side rasterizer, and ships a built-in
operability layer for AI agents — no third-party plugin, no special
build step. This file teaches an LLM how to use both halves.

------------------------------------------------------------------
WHAT QUI IS
------------------------------------------------------------------

  - Retained-mode (widget tree is persistent; events route through it).
  - Single Go module: github.com/qizhanchan/qui
  - Root package `qui` carries the engine (Window, events, layout,
    rendering, theme, BaseWidget, Container).
  - Subpackages:
      widgets/   concrete widgets (Button, TextField, Dialog, Tabs, …)
      scene3d/   3D scene graph + Viewport widget
      anim/      Tween / Spring / Timeline
      graphs/    2D charting on the Canvas
      svg/       SVG 1.1 subset (parse + rasterize)
      media/     audio + video playback
      webview/   embedded HTML/JS via CEF
      physics/   game physics (p2 / p3)
      agent/     AI-native operability server (this is what you want)
      examples/  runnable demos (reactive-html is the canonical one)

  - Cross-platform: macOS (full), Linux / Windows (partial — native
    dialogs / IME / emoji are darwin-only today).

------------------------------------------------------------------
HOW AI AGENTS DRIVE A QUI APP
------------------------------------------------------------------

In-process (Go API, always-on, zero overhead):

  import "github.com/qizhanchan/qui"

  widget, _ := window.Find("[role=button][name=\"Save\"]")
  _ = window.Click("#submit", qui.ClickOptions{})
  _ = window.Type("#email", "foo@bar.com", qui.TypeOptions{})
  img := window.SnapshotAnnotated(qui.AnnotateOptions{Scale: 0.4})
  tree := window.AccessibilityTree()
  _ = window.WaitIdle(2 * time.Second)

Out-of-process (a CDP-shaped protocol: JSON-RPC over WebSocket or
POST /rpc; MCP via `qui-agent mcp`):

  import "github.com/qizhanchan/qui/agent"

  // In your main(), after window.SetRoot(...):
  srv, _ := agent.BindEnv(window) // honors QUI_AGENT / QUI_AGENT_TCP env;
                                  // serves every window of the process

Then run the app with `QUI_AGENT=1 ./my-app` and drive it:

  qui-agent snapshot              # the UI as text, one [ref=@N] per node
  qui-agent click @14             # act on a ref (or any selector)
  qui-agent fill '#email' foo@bar.com
  qui-agent shot ui.png -annotate -scale 0.5
  qui-agent llm                   # the detailed guide + method reference

  # or any language over HTTP:
  curl --unix-socket "$SOCK" http://localhost/rpc \
    -d '{"method":"Agent.click","params":{"target":"[role=button][name=\"OK\"]"}}'

The full guide (domains, selector forms, error reasons, recipes) lives
at `agent/llm.txt` and is served by the running app at `/llm.txt`,
followed by a method reference generated from the live schema
(`/json/protocol`). This file is the orientation guide.

------------------------------------------------------------------
KEY CONCEPTS
------------------------------------------------------------------

  - Read before acting: Agent.snapshot (text, with @refs) or the
    Accessibility / DOM domains. Don't infer addresses from
    screenshots alone; an annotated screenshot labels every node with
    its @ref.

  - Every node has a nodeId: process-wide, stable for its lifetime,
    never reused, written @N in any selector. A ref whose node is gone
    fails with reason "stale_node" — it never points at another node.

  - Selectors: the widget grammar first, CSS for anything it rejects.
      @14   #id   [role=button][name="Save"]   [key=app.save]
      [role=button]:nth(2)   :focused   :layer(modal)
      button.primary   .row:has-text("invoice #42")   ul > li

  - Roles (stable): button, textbox, textarea, label, checkbox,
    radio, slider, spinner, combobox, listbox, listitem, tree,
    treeitem, table, row, cell, tabs, tab, scrollview, split, menu,
    menuitem, dialog, popup, tooltip, frame, colorpicker, viewport3d,
    video, webview, chart, container.

  - Modal-trap respect: an action targeting a widget hidden behind a
    modal dialog fails with reason "modal_blocked" — never
    silent-clicks through.

  - Actions auto-wait for their target, scroll it into view, resolve
    it once, and report focusChange / newOverlays / treeHash, so
    "did anything change?" needs no re-fetch.

  - Waits: Agent.waitForReady (first frame laid out and painted, then
    idle — run it after starting an app), Agent.waitFor {selector, state}, waitForIdle (paint +
    layout + animators + jobs quiescent), waitForStable (tree hash
    settled), waitForOverlay.

------------------------------------------------------------------
SECURITY
------------------------------------------------------------------

  - Unix domain socket by default — same-user, same-machine access
    only. Filesystem permission is the auth.
  - TCP requires QUI_AGENT_TOKEN bearer auth; WebSockets from web
    page origins are refused.
  - No eval. The action surface is declarative.
