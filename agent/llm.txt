# qui inspection protocol — operating a qui app from outside

You are driving a desktop UI built with qui (a Go retained-mode GUI
framework). The app speaks a CDP-shaped protocol (Chrome DevTools
Protocol): domains of methods and events, JSON-RPC messages. If you know
CDP, most of DOM / CSS / Accessibility / Input / Page / Overlay works the
way you expect. qui adds an Agent domain built for you — start there.

There is no JavaScript. Nothing evaluates code; you observe, act and wait.

------------------------------------------------------------------
THE 30-SECOND VERSION
------------------------------------------------------------------

  qui-agent snapshot                 # the UI, one line per node, [ref=@N]
  qui-agent click @14                # act on a ref from the snapshot
  qui-agent fill @20 "ada@example.com"
  qui-agent press @20 Enter
  qui-agent snapshot                 # see what changed

Or over HTTP (any language, curl):

  curl -s --unix-socket "$SOCK" http://localhost/rpc \
    -d '{"method":"Agent.snapshot"}'
  curl -s --unix-socket "$SOCK" http://localhost/rpc \
    -d '{"method":"Agent.click","params":{"target":"@14"}}'

Or as MCP tools: `qui-agent mcp` serves take_snapshot, click, fill,
type, press, select_option, take_screenshot, wait_for,
list_console_messages, get_html, get_styles, pick_element, … on stdio.

------------------------------------------------------------------
CONNECTING
------------------------------------------------------------------

Start the app with QUI_AGENT=1. It listens on a Unix socket
($TMPDIR/qui-agent-<pid>.sock, or QUI_AGENT_SOCK=path) and announces
itself in $TMPDIR/qui-agent/<app-name>.json. `qui-agent apps` lists
running apps; `qui-agent -app NAME …` picks one. With one app running it
is picked automatically; with several, qui-agent refuses to guess —
driving the wrong app reports success and screenshots the wrong window.

TCP is opt-in: QUI_AGENT_TCP=127.0.0.1:9222 plus QUI_AGENT_TOKEN (sent
as "Authorization: Bearer <token>").

Transports, same methods on both:
  POST /rpc                     {"method", "params", "target"?} → {"result"} | {"error"}
  WebSocket /devtools/browser/x app-level session (CDP-style, with sessionId)
  WebSocket /devtools/page/<targetId>  a session bound to one window
Discovery: GET /json/version, /json/list, /json/protocol (the schema).

------------------------------------------------------------------
NODES AND REFS
------------------------------------------------------------------

Every node has a nodeId: a process-wide number that never changes for
the node's lifetime and is never reused. Write it as @N anywhere a
target or selector is accepted. The DOM, AX tree and reactive component
tree share these ids, so @14 is the same element in all three views.

A ref that no longer resolves fails with reason "stale_node": the node
is gone (re-rendered away, dialog closed). Take a new snapshot. A ref
never silently points at a different node.

SNAPSHOT — Agent.snapshot / qui-agent snapshot

  # window-1 "Settings" 780x560
  - dialog "Confirm" [ref=@88] layer=modal[0]
    - button "OK" [ref=@90] [focused]
  - textbox "Email" [ref=@20] #email: ada@example.com caret=15
  - combobox "Method" [ref=@31] [haspopup]: GET options=[GET*, POST]
  - button "Save" [ref=@14] key=app.save [disabled]

  role "accessible name" [ref=@N] #id key=<message key> [states]: value
  Unnamed plumbing (layout boxes) is flattened away; children that only
  repeat their parent's text are omitted. params: root (subtree, by
  selector or ref), maxDepth, all (keep hidden + plumbing),
  format:"json" (the full nested tree with bounds, textState, options).

------------------------------------------------------------------
SELECTORS — when you have no ref
------------------------------------------------------------------

One string, two grammars, decided deterministically: whatever the widget
grammar accepts means what it means there; anything else is CSS.

Widget grammar (criteria AND together):
  @14                 node reference
  #id                 developer-assigned ID (htmlcss: the id attribute)
  [role=button]       exact role
  [name="Save"]       accessible name; also *= ^= $=
  [key=app.save]      message key the name was translated from
  [value=…]           current value
  :focused :visible :hidden :nth(0)
  :layer(root|modal|topmost)   restrict to the main tree / topmost modal

CSS (htmlcss apps): tag, .class, [attr=v], :nth-child, :not(),
combinators (a b, a > b, a + b, a ~ b), and :has-text("…") — matches the
innermost element whose text contains the string (case-insensitive):
  button:has-text("Save")    .row:has-text("invoice #42")

Note [name=…] is the widget grammar's ACCESSIBLE NAME. To match an HTML
name attribute, qualify it with a tag: input[name=email].

LOCALIZED APPS — prefer, in order: @ref (from a fresh snapshot), #id,
[key=…] (survives a language switch), role + structure, [name=…] last.

------------------------------------------------------------------
ACTING — the Agent domain
------------------------------------------------------------------

Every action takes "target" (selector or @ref), waits up to timeoutMs
(default 1000; 0 = no wait) for it to appear and be visible, resolves it
ONCE to a node, acts on that node, and returns:

  matched      {nodeId, role, name} — what was acted on
  focusChange  {from, to} nodeIds, when focus moved
  newOverlays  [{nodeId, layer}] — dialogs, menus, popups that opened
  treeHash     unchanged hash = the action changed nothing visible
  idleState    pending repaint / animations / jobs after the action

  click {target, button?, clickCount?, modifiers?}  or {x, y} for a raw point
  doubleClick, hover, focus, blur
  fill {target, value}     one-step SetText: one undo entry, change
                           handler fired. On a <select>/combobox it picks
                           the option with that label.
  type {target, text}      key by key — only for IME, key handlers, or
                           controlled-value races that fill skips
  press {target?, key}     Enter, Escape, Tab, Left, Cmd+Shift+Z, Ctrl+A
  selectOption {target, label | value}   no popup needed
  scroll {target, dx, dy}  wheel notches, positive dy scrolls down
  drag {from, to} or {x, y, x2, y2}
  pinch {target, scale}

Agent params are strict: a misspelt field ("selector" for "target") is an
invalid_params error, never a silently empty target.

`fill` on a node that takes no text (a heading, a plain div, a button)
fails with not_text_target and changes NOTHING.

------------------------------------------------------------------
WAITING
------------------------------------------------------------------

  Agent.waitFor {selector, state: visible|hidden|attached|detached}
  Agent.waitForIdle      no repaint / animation / job pending
  Agent.waitForStable    the tree hash held across two samples
  Agent.waitForOverlay {pattern: "modal", state: visible|hidden}
Each confirms on two consecutive frames. Actions already auto-wait for
their own target, so a wait is for what an action CAUSES.

------------------------------------------------------------------
ERRORS
------------------------------------------------------------------

error.data.reason tells you what to do:
  no_match         nothing matched — snapshot, adjust the selector
  stale_node       the @ref's node is gone — snapshot again
  modal_blocked    a dialog covers the target — handle it, or address
                   the dialog with :layer(modal)
  not_visible      matched, but hidden (collapsed tab, display:none)
  disabled         the control is disabled
  not_text_target  fill/type on something that takes no text; nothing
                   was changed
  bad_selector     the selector parsed in neither grammar
  timeout          a wait ran out, or the UI thread did not answer in 5s
                   (the app may be busy or wedged)
  ambiguous_target several windows — pass "target": "window-2" (HTTP),
                   attach a session, or qui-agent -target window-2
  target_closed    no such window / session
  invalid_params   wrong or unknown parameter names
  unsupported      no such method (GET /json/protocol lists them)

------------------------------------------------------------------
SEEING
------------------------------------------------------------------

  Page.captureScreenshot {scale?, clip?, annotate?, format?}
    annotate draws every node's bounds with its @ref, role and name — one
    image that shows the UI and how to address it. Captured at the end of
    the next frame, so it reflects every queued change.
  DOM.getOuterHTML {nodeId?}   the live tree as HTML — read back exactly
    what the app rendered (htmlcss apps: real tags, classes, attributes)
  CSS.getNodeStyles {selector | nodeId}   matched rules in cascade order,
    which declarations lost (active:false), computed values, box model —
    "why is this styled this way / why didn't my rule apply"
  Reactive.getComponentTree    mounted components, hook state, pending
    re-renders (dirty) — "why didn't my component update"
  Debug.getDiagnostics         layout overflow / misconfiguration

TEXT FIELDS: snapshot shows caret/selection; format:"json" adds
textState {value, caret, selStart, selEnd, preedit, canUndo, canRedo}.
Agent.valueChanged events carry source: user | program |
program-overwrite. program-overwrite right after the user's keystrokes
is a data binding writing a stale value back — the field "won't type".

------------------------------------------------------------------
EVENTS
------------------------------------------------------------------

Buffered (read any time): Target.getEvents {since, domains, limit}
returns events after seq `since` and lastSeq for the next call.
  Log.entryAdded            app logging routed through qui.LogHandler
  Runtime.exceptionThrown   a Go panic, with its stack
  Agent.inputRecorded / valueChanged / submitted
  Overlay.inspectNodeRequested, Target.targetCreated / targetDestroyed
Live (WebSocket session, after Domain.enable): the above plus
Page.frameCommitted, Page.windowResized, DOM.documentUpdated.

A panic normally ends the process (after being reported). With
Debug.setFlags {survivePanics: true} the frame or event is dropped and
the app keeps running, so you can inspect the state that broke it.

------------------------------------------------------------------
WORKING WITH THE HUMAN
------------------------------------------------------------------

  Overlay.setInspectMode {mode: "searchForNode"}  (qui-agent pick)
    The pointer becomes a picker; the user clicks the thing they mean and
    you receive Overlay.inspectNodeRequested {nodeId}. The click does not
    reach the app. Escape cancels.
  Overlay.highlightNode {nodeId | selector}  outline a node for them.

------------------------------------------------------------------
CONTROLLING CONDITIONS
------------------------------------------------------------------

  Debug.setFlags {paint, layout, layoutCache, draw, thread, widgets,
    i18nStrict, survivePanics}   the QUI_DEBUG_* checks, live, no restart
  Emulation.setDeviceMetricsOverride {width, height}   resize the window
  Emulation.setLocaleOverride {locale: "de-DE"}        switch language
  Emulation.setPageScaleFactor {pageScaleFactor}       viewport zoom
  Animation.setPaused / setPlaybackRate / advance {ms}
    freeze and step animations for deterministic screenshots

------------------------------------------------------------------
CHROME DEVTOOLS
------------------------------------------------------------------

With QUI_AGENT_TCP + QUI_AGENT_TOKEN + QUI_AGENT_DEVTOOLS=1 the app
logs a devtools:// URL; open it in Chrome to get the Elements, Styles,
Computed and Accessibility panes and a live screencast. The token rides
in the path (/devtools/t/<token>/page/<id>) because the frontend cannot
send headers. Console evaluation is not available (no JavaScript).

------------------------------------------------------------------
PROCESS LIFECYCLE
------------------------------------------------------------------

`kill <pid>` closes the app cleanly (OnClose runs, the socket and
discovery file are removed). `go run` does NOT forward signals to the
binary it spawns: build first (go build -o /tmp/app ./cmd/app) when you
need to kill it. Without a display, QUI_PLATFORM=headless renders
offscreen — screenshots still work.

LIMITS: WebView, scene3d.Viewport, media.VideoView and graphs.Chart are
opaque leaves — no descendant nodes inside them.
